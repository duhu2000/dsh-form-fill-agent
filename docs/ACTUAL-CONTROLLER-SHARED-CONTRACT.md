# 实际控制人共享字段契约与双智能体验收

日期：2026-09-07；发布目标：AI填表 0.2.12、数据清洗补全 0.8.13。发布及安装结果以 npm 和本机验收为准。

## 分层与维护入口

- 新增 `packages/qcc-field-contracts/lib/index.js`：唯一业务定义源，导出 `ACTUAL_CONTROLLER_GROUP` 和 `projectActualController`，维护字段 ID、中文名、别名、返回基数检查、百分比原文与字段级原因。纯 JavaScript、Node >=20，不包含网络、账号或 DSH。
- AI填表：`qcc-form-fill-provider` 依赖共享包，负责已授权 MCP 路由；`form-fill-core` 只新增通用 fieldIssues 透传，不包含企查查规则；应用负责搜索、显示核验原因和原列填写。
- 数据清洗补全：依赖同一个共享包，Host Bridge 与工作流目录直接导入契约。DSH 浏览器静态模块不解析 npm ESM，四字段展示/别名是轻量镜像，由跨目录和浏览器测试强制核对；提取逻辑不复制。
- 旧 128 字段目录未整体搬迁，保留历史 golden 回归；此次不是全部 Provider/Excel 内核的大规模迁移。

## 字段与边界

| 共享字段 ID | 页面/导出中文名称 | MCP 原始字段 |
| --- | --- | --- |
| actual_controller_name | 实际控制人名称 | 实际控制人名称 |
| actual_controller_direct_ratio | 实控人直接持股比例 | 直接持股比例 |
| actual_controller_total_ratio | 实控人总持股比例 | 总持股比例 |
| actual_controller_voting_ratio | 实控人表决权比例 | 表决权比例 |

工具：`get_actual_controller`，不以法定代表人、直接股东、受益所有人代替。不根据姓名推断自然人/机构性质。

仅当 `has_more=false`、游标为空、`total_count=1` 且明细确有一条有效控制人时自动补全。全部比例逐字保留，不相乘、不重算、不四舍五入。

- 多个控制人：不默认选第一人，也不拼接成貌似单个控制人；四字段留空待人工核验。
- 有下一页或总数不一致：视为不完整/异常，不根据当前一条推断唯一。
- 0 条记录、字段未披露、错误结构分别说明原因。
- 部分字段缺失不影响其他有效字段；既有非空单元格不覆盖。
- 实控人是补全字段，不是企业身份匹配锚点。截图中的长表头别名可自动映射；不设置泛化的“直接持股比例”别名，避免误映射为股东持股。
- 多控制人的候选选择/确认工作流未新增；本版在界面与下载的未完成/异常清单中明确标记，用户核验原始资料后可人工填写，不能由模型代选。

## 验收

共享投影覆盖唯一、多名、空记录、分页、数量不一致、缺失、对象污染、零比例和精度保留。

AI填表覆盖四字段分组、长表头别名自动匹配、真实 XLSX 原列写回、非空值保留、字段级未完成原因；隔离 Chromium 验证深浅色和桌面/窄屏。

清洗补全覆盖调用估算与单工具路由、共享对象一致性、表头别名、原列补空、字段原因导出和完整旧用例。界面“待核验”计数包含字段异常；企业主体候选与实控人字段核验分开，避免误用“确认主体”来选择控制人。

跨仓消费者验证用四个 tarball 独立安装（无 workspace 链接），回跑清洗补全完整 check 与旧场景以及 AI填表三套模板。只使用合成名单，无新增真实 QCC 调用。
