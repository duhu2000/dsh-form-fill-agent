# 填写范围与结果诊断收口

本次完善承接字段搜索与推荐，修复映射变更后仍复用旧向导字段选择的问题。

- 向导缓存绑定工作表、表头、映射、主体依据及服务端字段范围；签名变化或旧缓存缺少签名时重新加载当前范围，保留补充文字并提示重新检查。
- 整表无可用主体且无填写机会时禁止生成执行指令，提示映射实际企业名称列，不再默默使用整列空信用代码。
- 执行前展示未纳入的原表列，要求确认范围排除；筛选不会更改选择，不在此阶段自动发送或查询。
- “原文件导入名称”和“网址”可推荐目标字段，但须人工确认，不静默替换数据语义。
- 结果新增逐列可填写数、未完成数与原因分类；缺少主体按行统计，错误/空返回/候选歧义/字段排除分别解释。
- 工具返回附加 diagnostics，保留既有返回字段；日志明确“可填写”为预览，不能宣称已经写入或确认。生成副本仍有未完成项时明确提示。

## 验收

99 项单元/契约测试、三包打包检查通过。配置与原生 React 浏览器回归通过。

七列合成流程：名称列初始未识别、信用代码为空 → 阻止发送 → 手动修正映射 → 原两字段范围更新为六字段 → 手动排除一列时需确认 → 恢复全选并刷新 → 合成 Provider 查询六字段 → 确认导出六个非空单元格。原始名称保持不变。

另覆盖关键词/维度过滤、电话歧义推荐确认、持久选择、草稿保护、候选核验、取消/重试、工作台调宽和窄屏。

未修改客户文件、生产 profile 或旧任务；无真实 QCC 调用。实际客户剩余七行的来源问题仍需对应未完成清单，不能由合成测试推断已恢复。本次已随主包 0.2.3 发布，内核与 Provider 无改动。发布回执见 [0.2.3](RELEASE-0.2.3.md)。
