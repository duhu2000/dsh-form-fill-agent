# 候选能力与执行状态收口（待发布）

基线为主包 0.2.19；本轮没有发布或重启生产 DSH。

## 修复与原因

- 重复列：仅在推荐时去掉末尾「（重复列 N）」标记，保留原表名称及按位置映射的独立性。
- 受益人、主营业务收入：此前发布依赖没有对应 Provider 能力，仅补 UI 别名不足以填表。本轮接入 get_beneficial_owners/get_financial_data，目录增至 137 字段，推荐仍需人工采用。
- 受益所有人只取返回首条，不代表唯一或最大受益人；财务只取首个返回报告期，空值不跨期补取，保留金额原值及来源报告期。主营业务收入与营业总收入的区别在候选处明确提示。
- 取消未纳入列的额外勾选门槛，保留范围摘要和明细。仍需用户发送草稿后执行查询，仍需确认结果后写副本。
- 回填后工作台进入主体核验；轮询检测到执行状态后同步进度并切换步骤，执行结束进入预览。进度不表示填写成功。

## 边界及验证

首条投影实现取自本仓主线共享契约 0.2.0 的 snapshot-fields.js，暂作为 Provider 内部模块接入，避免改动当前共享包依赖链；后续共享包统一时应移除这份内部实现。当前未发布依赖仍是旧版本号，正式发布须为 Provider 分配新版本并同步主包精确依赖，不能覆盖已有 0.2.1。

117 项测试、四包打包检查通过。合成测试验证首条取值、首期缺失不跨期、0 值、报告期来源、原表已有值保留和 Provider 工具调用。

原生 React 测试 Host 的草稿追加/替换、工作台恢复及普通会话隔离回归通过。

浏览器验证包含 60 行模板、受益人/主营业务收入/重复列候选及说明、480 个位置范围、取消额外勾选、刷新恢复、深浅色窄屏。延迟合成 Provider 验证执行中自动同步与结束切换。配置导出回归通过；真实企查查账号调用与真实 DSH 模型全链路尚未验收。
