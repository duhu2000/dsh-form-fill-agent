## 2. 查阅清洗插件任务所得

存在两个同名任务“DSH插件-【数据清洗补全 智能体】”：
- 01a05608-8c8c-7632-8f93-f7f94a044640：原规划、双仓分工与移交。
- 01a0560a-cabd-7ce1-ad6a-e07dabc0875b：实际开发。任务读取接口的最近两轮未返回正文，补读对应本地会话记录，核对 2026-09-06 的用户问题及设计答复。
- 交叉核对旧仓 docs/UI-LAYOUT-0.8.7.md、docs/UI-WORKFLOW-V2.md、docs/DSH-ENTRY-UI-PLAN.md 及 f17ecc4。旧入口方案是历史上下文；当前页面职责以 0.8.7 为准。

用户原问题：首页快捷按钮与右侧流程重复；首页大介绍卡挤压输入框；提示词弹窗偏下、被裁切，长内容和底部操作难以使用。

0.8.7 的明确结论：
1. 首页表达任务，向导组织任务，工作台核验/执行/查看结果，对话解释与协作。
2. 输入框下的按钮是导航，不是执行步骤，也不直接触发查询。
3. 工作台有“当前任务 / 任务历史”两层，历史不混进五步流程。
4. 取消首页大介绍卡；说明折叠进工作台；右侧首次默认收起。
5. 向导居中、内容内部滚动、底部动作固定；回填后聚焦原生输入框，不自动发送。
6. 菜单、向导、工作台使用同一 taskId。开始新任务成功后才清理旧浏览器状态，不删除历史与制品。
7. 仅移动自有 DOM；共享槽位和其他插件内容保留，缺失标记回退，不修改安装的 DSH bundle。

清洗插件文档记载 213 tests 与 8 组 React/Chromium 布局回归通过。但后者是复刻宿主层级的组件验收，不是全部真实宿主/第三方组合 E2E。本计划继续保留这条证据边界。

## 3. 目标页面及职责

| 表面 | AI填表拟议内容 | 不承担的操作 |
|---|---|---|
| 首页 | AI填表标题、一句话说明、原生 Composer、提示词生成、下方快捷菜单 | 大面积产品宣传、第二套流程、自动查询 |
| 提示词向导 | 上传表格、识别工作表与主体列、选择要填字段、形成可编辑指令 | 默默发送、猜测主体、覆盖已有值 |
| 右侧工作台 | 当前任务摘要、五步流程、完整表格/变更预览、未完成项、结果、历史 | 另起 taskId 或重复发起查询 |
| 对话 | 表达要求、解释结果、触发已授权高层工具 | 搬运全量原始名单和工具原始响应 |
| 独立 /form-fill/ | 同一任务视图的降级入口及独立演示 | 维护另一套业务状态 |

建议首页文案：“上传已有表格，识别可填写的空位，确认后生成新副本。”
快捷菜单：“导入表格｜字段设置｜主体核验｜填写预览｜任务历史”。前三者定位对应工作台阶段，预览定位第四阶段，历史独立。无前置条件时显示下一步指引，不伪装为已开始执行。
三套示例放进导入页；醒目标注合成示例，与真实来源模式分开。实际上传先做本地结构分析，不能用 mock 查询无匹配来暗示真实企业不存在。

工作台五步：
1. 导入与识别：文件、工作表、表头、记录锚点、受限结构说明；可看完整输入。
2. 字段与规则：原字段→目标字段、待填空位、排除项、只填空白规则；允许修正映射。
3. 主体核验：完整名称/代码、精确匹配/候选/未匹配/失败分流；候选人工选择。
4. 填写预览：逐格原值、新值、来源工具/字段/获取时间、选中状态、未完成原因。
5. 确认与下载：冻结选中 ChangeSet、生成新副本、完整变更与未完成项下载。

管理层：当前任务 / 任务历史。历史只列当前允许范围的元数据、阶段、时间、过期状态和恢复入口；不能直接开放全局任务枚举。

## 4. 关键交互与工程缺口

- 同一任务主状态由 Host 提供；组件不能各自创建平行任务。新增文件名、显示标题、阶段、workspace/session 归属、updatedAt、revision、结果引用等元数据。
- 任务 ID 与授权分开设计。当前随机 ID 是访问凭据；增加历史列表前必须限定工作区和会话访问边界，不能把全局 tasks Map 直接暴露给网页。
- 引入 expectedRevision 写入检查。现有 revision 有存储但不是完整公开并发契约；旧摘要、旧候选确认、双标签页操作应返回明确冲突。
- 拟议状态：draft → analyzed → configured → resolving → review_required / resolved → enriching → preview_ready → completed；另有 authorization_required、partial、failed、cancelled、expired。
- 运行中的记录重启后标记 interrupted，不自动重复远端调用。确认完成任务可重建输出；新建草稿、关闭向导和重启不得删除旧制品。
- 恢复链接、侧栏和对话工具卡打开相同 taskId；无效/过期链接给恢复说明。
- 先完成“回填到当前业务会话并聚焦”，保留人工发送；再做工具状态自动同步。默认不再要求复制 UUID 和手工刷新。
- 验证当前 workspace/session 绑定及归属，不沿用 cwd-only 创建会话造成输入区不可用的旧问题；不得劫持普通 New Session。
- DSH slot 与工具调用 API 实施前查本地目标版本源码并做隔离探针。Portal 只用于已验证的自有节点定位；缺依赖回退独立页，不硬依赖第三方 sidebar。
- 能力状态分离：演示可用 / QCC 未连接 / 需要授权 / 工具可用 / 正在执行。当前 health 的 mock-only 不能代表整个产品真实 Provider 状态。
- 将“置信度 100%”改为准确的来源/匹配依据表达。当前数值是程序赋值，不能表现为 QCC 返回的概率。
- 已有整包导出能力保留；新增逐格/批量排除后，必须重新生成 ChangeSet 摘要并再次确认，不能仅在前端隐藏行。
- 所有数据表完整可达：分页/虚拟滚动、总数、筛选、完整下载，避免清洗插件历史上仅显示前 5/8 行的问题。

暂不把 Word、任意复杂 Excel、全量 128 字段迁移、风险评分或多用户云服务塞入首页改版。

## 6. 拟议代码落点

以下为拟新增/拆分模块，当前不存在的文件不代表已经交付：
- agent/lib/client.js：收敛为装载、能力探测与生命周期入口。
- agent/lib/client/：home、wizard、workbench、task-history、session-adapter 和样式；须验证 DSH 无构建加载方式或选定构建方案后落地。
- agent/lib/task-service.js、task-contract.js：阶段、版本和授权范围；http.js 仅适配请求。
- agent/lib/task-store.js：schema 迁移、任务索引和损坏记录处理；保留旧读取/导出兼容。
- agent/lib/workflow.js：本地 analyze/configure 与远端 enrich 分离；高层工具不绕过前置条件。
- core：仅通用文档识别、映射、计划和 ChangeSet，不引入 React/DSH/产品导航。
- provider：实体识别与工商适配、字段来源、错误类别；目录扩展先做契约再迁移。
- test/ 与 scripts/：会话隔离、UI、完整清单、候选、并发、迁移、真实 DSH 端到端、双消费者门禁。

不直接复制清洗插件的大型 client.js，也不立即新建共享 UI 包。先复用经过验证的布局规范与测试案例；只有两产品组件契约稳定且差异清楚后才评估抽取。旧仓发布主线继续由其任务维护。
